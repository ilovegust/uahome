# 우아홈 운영 도구

**1688 사입 → 쿠팡 로켓그로스 판매**를 위해 상품 후보를 비교하고, 수입 비용과 마진을 계산하고, 발주·상품등록·고객 리뷰 답변을 검토하는 **내 컴퓨터용 반자동 운영 앱**입니다.

## 지금 할 수 있는 일

| 업무 | 앱이 준비하는 것 | 직접 확인할 것 |
| --- | --- | --- |
| 상품 선정 | 수요·경쟁·공급처 평가와 목표 마진 기준의 후보 점수, 검색·비교 | 실제 수요 근거와 공급처 신뢰도 |
| 사입 | 수량·MOQ·환율·입고비를 반영한 발주 검토서, 승인 대기 | 견적·옵션·납기 확인, 실제 주문과 결제 |
| 수입원가 | 위안화 단가·환율과 중국 내 배송·국제 운송·관세·수입부가세·통관·검수·라벨·국내 입고비를 수량별 배분, 현금 지출과 원가 구분 | 견적 금액·부가세 공제 여부 |
| 마진 계산 | 그로스 입출고·배송·보관비, 포장·수수료·광고·반품·세금 예비비, 손익분기·목표 판매가 | 판매처 실제 요율과 세무 처리 |
| 상품 등록 | 입력된 특징·규격 기반 제목·설명·키워드 초안, 공통 CSV | 필수고시·인증·이미지 사용권·옵션·재고 확인, 판매처 등록 |
| 리뷰 관리 | 실제 리뷰 저장, 답변 초안, 문제 리뷰 확인 표시, 답변 승인 | 답변 내용 확인과 판매처에서 전송 |
| 일괄 준비 | 선정 상품의 사입 요청, 입고 상품의 등록 요청, 미작성 리뷰 답변 준비 | 승인함에서 항목별 검토 |

현재 판매처·사입처 API와 생성형 AI는 연결되지 않았습니다. 상품 점수는 수동 평가 기반이고 초안은 규칙·서식 기반입니다. 실시간 상품 검색, 자동 주문·결제, 판매처 직접 게시, 고객 리뷰 자동 수집·전송은 아직 수행하지 않습니다. CSV는 공통 자료이므로 판매처별 업로드 양식에 맞게 변환해야 합니다.

현재 계정 준비 상태는 **쿠팡 판매자 등록 완료 / Open API 발급 전**입니다. [다음 연결 단계](docs/next-steps.md)를 참고하세요.

## 처음 실행하기

**Python 3.12 이상**이 필요하며 추가 패키지는 설치하지 않아도 됩니다.

1. GitHub의 **Code → Download ZIP**으로 내려받아 압축을 풉니다.
2. Windows에서는 `start-uahome.bat`를 더블 클릭합니다. Python이 없다면 먼저 설치해 주세요.
3. 브라우저에서 `http://127.0.0.1:8765`가 열립니다. 실행 창을 닫으면 앱도 종료됩니다.
4. **상품 추가**로 시작하거나 **예시 데이터 불러오기**로 사용 흐름을 확인합니다. 예시는 실제 시장 데이터가 아닙니다.

Mac/Linux 또는 터미널에서는 압축을 푼 폴더에서 실행합니다.

```bash
python3 launch.py
```

브라우저 자동 열기 없이 서버만 실행하려면:

```bash
python -m uahome
# 다른 포트나 DB 위치를 사용하려면:
python -m uahome --port 8766 --database data/my-shop.sqlite3
```

## 매일 사용하는 순서

1. 후보 상품에 1688 URL·단가(CNY)·판매가·수량과 평가 근거를 입력합니다. 마진 화면의 **1688 수입원가 배분**에서 실제 환율·전체 물류/통관 견적을 입력하고 선택 상품에 원가를 저장합니다. 계산 근거는 상품 메모에 보존합니다. 수입부가세 공제 여부를 선택하면 현금 지출과 운영 원가가 구분됩니다.
2. 마진을 검토하고 상태를 **사입 검토**으로 바꿉니다.
3. **검토할 작업 준비** 또는 사입 초안 화면에서 승인 요청을 만듭니다. 승인함에서 금액·수량을 확인해 승인합니다.
4. 사입처에서 직접 주문한 다음 승인함에 **외부 수동 완료**를 기록합니다. 상품은 발주 상태가 됩니다.
5. 실제 입고 후 상품 상태를 **입고 완료**으로 바꾸고 필수 상품 정보를 채웁니다.
6. 등록 초안과 CSV를 확인하고 승인합니다. 쿠팡에서 직접 등록한 뒤 수동 완료를 기록합니다.
7. 판매자 SKU·쿠팡 상품 ID·센터·입고계획 번호·운송장을 기록하고 **센터 입고 준비 → 센터 이동 중 → 센터 입고 확인**으로 실제 입고 상태를 관리합니다. 등록 완료는 판매 가능 재고 확인을 의미하지 않습니다.
8. 실제 고객 리뷰를 입력하고 답변 초안을 저장·검토·승인합니다. 판매처에서 답변한 뒤 수동 완료를 기록합니다.

사입·등록 문서 화면에서 편집한 텍스트는 복사·다운로드용입니다. 승인 요청의 스냅샷은 저장된 상품 정보를 기준으로 생성하므로, 승인할 내용은 상품 정보에 반영하고 다시 생성하세요. 리뷰 답변은 **답변 저장** 후 승인합니다.

승인 요청 이후 상품·비용·리뷰가 바뀌면 이전 승인으로 완료할 수 없습니다. 기존 요청을 반려하고 변경된 내용으로 재요청하세요.

## 데이터 저장과 백업

- 데이터는 로컬 `data/uahome.sqlite3`에 저장되어 재시작 후에도 유지됩니다.
- **설정·백업**에서 JSON 백업을 다운로드할 수 있습니다. 브라우저 캐시가 아닌 파일 백업을 보관하세요.
- 화면에서 복원할 수 있는 JSON 파일은 10MB 이하입니다. 백업 복원은 현재 데이터를 **대체**합니다. 복원 전 현재 백업을 보관하고 확인창을 읽어 주세요.
- 고객명·리뷰·공급처 가격이 들어 있는 DB·백업을 공개 저장소에 올리지 마세요. 운영 DB는 `.gitignore`로 제외했습니다.
- 이 앱은 `127.0.0.1`에만 바인드하는 로컬 단일 사용자 버전입니다. 인터넷에서 접근하는 운영 서비스로 바꾸려면 로그인·권한·HTTPS·서버 저장소·백업 운영을 먼저 추가해야 합니다.

## 계산 기준

모든 배송·포장·기타 비용은 **개당 금액**입니다. 입고 운임 총액을 입력하지 말고 수량으로 나누어 입력하세요.

```text
매출 = 판매가 + 고객 부담 배송비
환산 사입 원가 = 사입가 × 원화 환율 + 개당 입고비
반품 예비비 = 반품률 × 건당 추가 반품비
총비용 = 환산 사입 원가 + 그로스 입출고·배송비 + 예상 보관비
       + 별도 출고비 + 포장비 + 기타비 + 고정수수료
       + 반품 예비비 + 매출 × (플랫폼·결제·광고·세금예비비 비율 합)
예상 이익 = 매출 - 총비용
마진율 = 예상 이익 ÷ 매출 × 100
```

비율은 모두 배송비 포함 매출에 적용합니다. 실제 판매처와 기준이 다르면 요율·기타비를 조정하세요. 세금 예비비는 단순 추정치로 실제 부가세·소득세 계산이 아닙니다. 반품에 따른 상품 손실·환급되지 않는 수수료는 추가 비용에 포함하세요. 비율 합계가 계산 가능한 범위를 벗어나면 목표 가격을 표시하지 않습니다.
